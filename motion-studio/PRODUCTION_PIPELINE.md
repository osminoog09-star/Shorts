# M1lash Studio — работающая очередь агентов (v0.3)

Добавлено после первого реального задания: issue #54 «Как появился табак».
Этот проект не обещает «снять фильм без ресурсов» — разделяет готовые исследовательские файлы, черновики и настоящие медиа.

## Что работает после публикации workflow в main
1. На сайте создаётся GitHub Issue с проверяемым JSON. Владельцем может быть только osminoog09-star.
2. Workflow автоматически запускается при создании новой задачи. Для уже созданного issue #54 владелец пишет отдельный комментарий **/studio run** (именно эту строку без другого текста).
3. Из репозитория загружается редакционно подготовленный source pack для issue #54: 9 источников, 8 фактологических утверждений, 7 актов на 25 минут; записываются research.md, facts.json, director_and_art_prompts.md и scene_cues_provisional.json.
4. На каждый факт даются минимум два источника; все получают метку REQUIRES_FACT_CHECK — ссылки не являются доказательством, что робот сверил полный документ.
5. Опционально — создаётся реальный 7-главный черновик сценария в Gemini 3.8 Flash text API с токенами фактов, проверкой объёма и контролем на выдумывание. Это НЕ включается без двух условий: собственный секрет GEMINI_API_KEY и репозиторная переменная M1LASH_TEXT_AI_ENABLED=true. В большинстве случаев запрос расходует квоту/кредиты API; бесплатность не гарантирована.
6. Пакет файлов сохраняется в GitHub Actions artifact на 14 дней. Финальный stages.json и PROGRESS.md явно описывают, что получилось.
7. Bot публикует структурированный отчёт в комментарии issue. Страница «Производство» показывает статус каждого агента, что готово и что заблокировано. Ссылка ведёт к отчёту GitHub Actions; никаких API ключей в Pages.
8. Перезапуск через /studio run работает только для комментариев владельца репозитория и только на issue с префиксом [M1LASH STUDIO]. Бот не реагирует на свои же комментарии.

## Почему не все этапы «зелёные»
- Исследователь и режиссёр готовят реальную исходную базу и постановочные задания.
- Фактчекер **не может автоматически утверждать каждую историческую деталь**, даже когда две ссылки указаны. Для публикации человек проверяет каждое существенное утверждение.
- Сценарист работает только при включённом Gemini API. Если модели нет или она ответила слишком кратко, честный BLOCKED, без ложного готового сценария.
- Художник пока выпускает только промпты, **не** кадры и не лицензии.
- Дима ru-RU-DmitryNeural **не генерируется** этим pipeline: без принятого сценария нельзя утверждать наличие подходящей речи.
- Для настоящего видео 21+ мин нужен исходный MP4, рендер оригинальных кадров, лицензии и python scripts/qa/longform_duration_gate.py. Ни тишиной, ни автослайд-шоу правило не обходится.
- Кинонарезки и большие коммерческие продакшн-процессы требуют отдельного пути и прав.
- Новые запросы, для которых ещё нет утверждённого источникового пакета, получают BLOCKED_NEEDS_SOURCE_RESEARCH. Редакционный пакет для любой темы нельзя выдумывать.

## Безопасность
- Данные GitHub Issues публичны. Не вставлять документы клиентов, секреты, чужие приватные видео, пароли или контакты.
- Включить Gemini API только после оценки цен и лимитов. В browser JS ключей нет, нет публикации на YouTube.
- Любой модельный ответ или содержимое чужого видео считается непроверенным материалом, не инструкцией к исполнению.
- Готовый ролик не декларируется до настоящего QA, прав и одобрения владельца.
- GitHub Actions workflow может запускаться с задержкой, а открытый GitHub API ограничивает частоту загрузки статусов; статус «не получен» не значит «всё выполнено».
