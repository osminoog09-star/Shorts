# M1lash SCAN 2.0 — независимый аудит PDF @siddhantt.ai

Дата оценки: 2026-10-28. Источник: присланный пользователем SCAN-System-by-siddhantt.ai.pdf (8 стр.).

## Вердикт
Использовать методику поиска *необычно успешных видео небольших каналов*, но НЕ доверять рекламным числам как гарантированным и НЕ устанавливать неаудированный сторонний ZIP SidIQ-scanner с Google Drive. Разработан собственный Python scanner (без NPM, без YouTube-скачивания).

## Из PDF: факт, гипотеза, ограничение
- Стр. 1/4: автор заявляет 1 283 видео за 4 минуты, 11 каналов, 14.2 млн просмотров. Это данные PDF, независимого лог-файла/файла результатов с SHA нет. Нельзя писать, что мы повторили этот запуск.
- Стр. 3: предложена загрузка стороннего ZIP с js и локальным youtube_key.json. В нашей публичной студии ключ только через GitHub Actions Secrets; сторонний ZIP не загружается и не исполняется.
- Стр. 4: разница просмотров одного видео и медианы последнего десятка публикаций канала действительно полезна. Но медиана с текущими lifetime просмотрами без возрастного выравнивания и выбора той же длительности может давать сильное смещение. Нужны >=5 старых роликов того же формата; при недостатке — NULL, а не 0 или ложные 10x.
- Стр. 4: lifetime views / elapsed days — это СРЕДНЕЕ за всю жизнь видео, НЕ текущий growth/day. Для недавнего темпа нужны минимум два реальных замера со временем.
- Стр. 5: 11 каналов имеют *разную* длительность: 1, 8, 13, 21, 24, 30, 31, 34, 52, 64, 69 минут. Фраза про «все 20–60 минут» внутренне противоречит таблице. Без ведущего, исходники стоков и темп выпуска нельзя автоматически подтвердить YouTube Data API.
- Стр. 6: локальные Whisper, Kokoro, Wan2GP и т.п. возможны, но каждый инструмент требует отдельного license/security/resource теста. Kokoro v1.0 не включает штатный русский голос, поэтому не заменяет Диму/Свету.
- Стр. 7: идея обучения режиссуре и структуре конкурента полезна; копировать кадры, музыку, визуальный дизайн и речь без прав нельзя. Материалы NASA обычно доступны для редакционного контекста, но логотипы, сторонние права и коммерческое использование имеют ограничения.
- Стр. 8: $8–16k vs $400–800 при 4 млн просмотров — только арифметика от заданных RPM и при полной монетизации, не прогноз M1lash. В 2026 YouTube monetization требует оригинального, не массового и не повторяющегося низкоценного контента. Внутреннее правило M1lash >=21:00 не является обязательным правилом YouTube для mid-roll: официальный порог 8 минут.

## Проверенные первоисточники
- Новые default quotas YouTube Data API: https://developers.google.com/youtube/data/determine_quota_cost
  На 2026-10-28: до 100 search.list calls/day (отдельный bucket), 1 unit/call, прочим endpoint стандартно 10,000 units/day. Это НЕ старые 100 units/search и 10,000 total quota.
- search videoDuration long: https://developers.google.com/youtube/data/reference/rest/v3/search/list
  Filter long означает >20 минут, поэтому наш код дополнительно проверяет >=1260 сек. regionCode=US ограничивает доступность в США, не доказывает США-аудиторию.
- Channel count: https://developers.google.com/youtube/data/reference/rest/v3/channels
  Subscriber count округлён до 3 значащих цифр. Числа в UI только приблизительны.
- YouTube monetization: https://support.google.com/youtube/answer/1311392
  Массовые однотипные шаблонные видео и слайд-шоу с низкой ценностью могут быть не допущены к монетизации.
- Mid-roll videos >=8m: https://support.google.com/youtube/answer/6175006
- NASA media exceptions: https://www.nasa.gov/nasa-brand-center/images-and-media/
- YouTube Data API revised viewCount: https://developers.google.com/youtube/data/reference/rest/v3/videos
  Не путать API viewCount и engaged views/удержание.

## Что реально реализовано в ветке Studio 2.0
- motion-studio/automation/outlier_radar.py:
  - 12 ключевых английских запросов, до 50 результатов каждый, не больше 12 поисков за запуск; при запуске каждые 12 ч — 24 поисковых вызова в сутки (не включая другие workflows).
  - Запрашивает данные video/channel/uploads playlists, фильтрует 21+ минут, каналы с округлённым subscriberCount не более 300 тыс.
  - Сравнивает кандидата с 5–10 более ранними роликами канала того же формата. Отношение views/median=outlier_ratio. Это приближение, не удержание и не историческая медиана при одинаковом возрасте.
  - Сохраняет реальные timestamps; недавний рост только как положительный delta views между сканами с интервалом 1–96 ч.
  - Явно оставляет неизвестными: faceless, реальная география аудитории, RPM, watch time, retention, rights.
  - Не загружает YouTube видео и не требует сторонний ZIP.
- .github/workflows/m1lash-outliers.yml: 06:37 и 18:37 UTC, 12-минутный timeout, offline тесты, key only from YOUTUBE_API_KEY secret; без ключа никакой выдуманной статистики. GitHub Schedule может задерживаться.
- motion-studio/data/outliers.json: начальная пустая запись; заполнится при реальном API-запросе.
- Вкладка «Радар новостей» на сайте: карточки аномальных длинных видео с outlier ratio, средней скоростью, фактическим приростом при втором замере, ссылкой на YouTube и кнопками для ОРИГИНАЛЬНОГО проекта Shorts или 21+ мин.
- tests/test_m1lash_outlier_radar.py: локальная симуляция API и проверка 21 мин, квоты, медианы, второго замера, границ и отсутствия выдуманных данных.

- Полная автоматическая продакшн-линия с нулевым человеческим участием и выпуском оригинальных MP4 не подключена, нельзя объявлять заявки завершёнными.
- Не подключена ручная классификация «без ведущего» на основе разрешённого видеоконтента.
- Ключ, собственные издательские права и согласие владельца канала должны остаться вне GitHub Pages, пользовательских Issues и публичных JS.

## Следующее улучшение после реального первого скана
1. Измерить реально доступные 12 запросов и quota bucket, не превышать лимит.
2. Вывести лидеров в топ-15 с аннотацией «источник/надёжность».
3. Второй замер через >=12 ч даст реальную динамику (при повторном обнаружении видео).
4. Режиссёр+исследователь создают собственный сюжет с 2+ независимыми факт-источниками; Dima/Sveta; оригинальные ассеты и аниматик; 21+ мин gate.
5. До публикации — ручная проверка источников, музыки, визуала и прав; минимальное качество >=8/10.
