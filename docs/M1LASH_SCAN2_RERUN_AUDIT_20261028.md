# Повторный независимый аудит SCAN 2.0 и M1lash Studio — 28.10.2026

## Источники и границы
- Основной источник методики: загруженный пользователем PDF SCAN System (8 страниц). Числа 1283 видео, 11 каналов и 14.2 млн просмотров — заявления автора, не повторённый нами результат.
- YouTube API quota: https://developers.google.com/youtube/data/determine_quota_cost — 100 search.list вызовов/день по умолчанию, 1 unit/call; другие endpoints объединены в 10 000 unit/day. Возможны индивидуальные лимиты.
- videos.list: https://developers.google.com/youtube/data/reference/rest/v3/videos/list — maxResults НЕ поддерживается совместно с id.
- playlistItems: https://developers.google.com/youtube/data/reference/rest/v3/playlistItems — contentDetails.videoPublishedAt = дата выхода видео; snippet.publishedAt = добавление видео в список.
- search.list: https://developers.google.com/youtube/data/reference/rest/v3/search/list — videoDuration=long означает >20мин; отдельно фильтруем >=21:00.
- YouTube monetization: https://support.google.com/youtube/answer/1311392 — массовые шаблонные ролики без существенной оригинальности рискуют не пройти проверку.

## Проверка исходного PDF
1. На стр. 5 таблица смешивает видео в 1, 8, 13 и 21–69 минут, а текст утверждает общую характеристику 20–60 минут. Эту выборку нельзя трактовать как доказательство, что только длинный контент растёт.
2. На стр. 4 «просмотры за день» по общему просмотру/возрасту — средняя с момента публикации, не истинная текущая динамика.
3. На стр. 3 скачиваемый сторонний ZIP не прошёл аудит; не запускаем, наш сканер собственный.
4. На стр. 8 расчёты RPM лишь сценарии, а не гарантия монетизации M1lash.

## Реально выявленные и исправленные ошибки ПО
### P0: недопустимые параметры YouTube Data API
- Было: `videos.list(id=..., maxResults=50)` через generic `batched()`.
- Теперь: `videos.list(id=...,part=...)`, не передаём `maxResults` в запросах по id.
- Новый regression test специально отвергает неподдерживаемую комбинацию; одна симуляция API без проверки параметров не считается реальным подтверждением.

### P1: ошибка даты загрузки в истории канала
- Для медианы прежних роликов раньше можно было использовать дату добавления в плейлист, а не публикации видео.
- Теперь приоритет `contentDetails.videoPublishedAt`; тестовый ответ намеренно содержит обе несовпадающие даты.

### P1: один недоступный канал останавливает весь скан
- Добавлен per-channel fallback `baseline_status=UNAVAILABLE_NO_RATIO`, без ложного outlier ratio. Другие каналы продолжают обрабатываться.

### P1: непоказанные на Pages новые данные
- После коммита со стороны GITHUB_TOKEN новый push не запускает очередной workflow Pages сам по себе.
- Workflow получает `actions:write`, после подтверждённого успешного сбора делает `gh workflow run motion-pages.yml --ref main`.
- При отсутствующем ключе нет изменений и нет ложной публикации; при ошибке скана сохранить старые данные и fail closed.

### P2: сайт ранее проверялся только статическими тестами
- Добавлен реальный Chromium smoke-test на desktop и mobile: открытие формы, переключение формата, список 21 стиля, лента новостей, пустой SCAN, переключение разделов, мобильный overflow, отсутствие JS-ошибок.
- Не путать UI smoke с оценкой готового профессионального видео (озвучка, монтаж, анимация).

## Что остаётся неподтверждённым
- Настоящий запрос к YouTube с YOUTUBE_API_KEY: последний проверенный Actions вывод был `SCAN status=not_configured candidates=0`. Без владельца/ключа этого не исправить.
- Качество, реальный вклад в просмотры, подписчики конкурентов, фактическое удержание и монетизация: без live API/YouTube Analytics нет доказательства.
- Полный браузерный тест нового SCAN выполняется отдельно в CI; без успешного результата не заявлять прохождение.
- Монтаж видео 21+, бесплатный локальный GPU генератор, стабильность Дима/Света и настоящая публикация этим сканером не тестировались.
- Данный PR остаётся черновиком; зелёный CI не заменяет интеграционный тест с настоящим API и одобрение владельца.

## Контроль до публикации
- Выполнить хотя бы один реальный SCAN с зарегистрированным YouTube Data API key, после 12+ часов — повторный замер одного и того же video_id.
- Убедиться, что обновление data/outliers.json действительно появилось на Pages через отдельно запущенный deploy.
- Выбрать две потенциальные темы, проверить факты по 2 независимым источникам, затем провести режиссёрский/правовой аудит до создания MP4.
