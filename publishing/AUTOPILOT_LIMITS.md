# M1lash — автопубликация и лимиты (26.10.2026)

## Что работает сейчас
- До миграции **Metricool** продолжает выкладывать существующие публикации. Не переносить их вторично и не отменять.
- \`youtube-direct.yml\` умеет безопасно загружать **готовый, проверенный MP4** по манифесту как PRIVATE+publishAt, только после действительного Google OAuth и проверки RU/EN channel ID.
- Новый \`youtube-autoqueue.yml\` **один раз в день** ищет готовые манифесты и запускает существующий direct uploader. Он НЕ генерирует сценарии, видео, голоса и изображения, не покупает кредиты. Без OAuth не отправляет.
- Новая очередь **выключена** по умолчанию дважды: \`publishing/autopilot.json:enabled=false\` и GitHub variable \`YOUTUBE_AUTOPUBLISH_ENABLED\` не равна \`true\`. Включать только после подтверждённого OAuth, проверки нового календаря и готового исходного видео. Тестировать через Actions → YouTube · guarded autopublish queue → Run workflow → dry_run=true.

## Включение (когда один раз настроен Google OAuth)
1. Настройте GitHub Secrets из [publishing/README.md](README.md): client ID, client secret, RU refresh token. Не присылать их в чат и не сохранять в репозиторий. Google client secret, ранее показанный в чате/скриншоте, лучше перевыпустить.
2. В [YouTube auth check](https://github.com/osminoog09-star/Shorts/actions/workflows/youtube-auth-check.yml) запускайте \`channel=ru\`. Только сообщение \`SUCCESS\` подтверждает, что refresh token и канал совпадают. Английский канал отдельно.
3. Пройдите офлайн-тесты, убедитесь, что действующая очередь Metricool не содержит будущей записи в выбранное время. Не активировать до 03.11; если дополнительные ролики Metricool появились позже — продлить \`migration_hold_until\` и повторно проверить.
4. Создайте файл \`publishing/queue/<slug>.json\` только для **нового, ещё нигде не назначенного** MP4. Поля исходного манифеста как в \`publishing/examples/heron-scheduled.json\`, а также:
   - \`"auto_publish": true\` — разрешение на автономную отправку именно этого файла;
   - \`"approved": true\`, \`"quality_checked": true\` — подтверждён полный просмотр/прослушивание;
   - \`"rights_checked": true\` — права на видео, музыку, голоса, иллюстрации проверены;
   - \`"metricool_clear": true\` — нет дубля в Metricool/YouTube;
   - \`source.sha256\` — **настоящий** SHA-256 выбранного MP4, не выдумывать.
5. В \`publishing/autopilot.json\` переключите \`enabled\` в \`true\`, в GitHub Settings → Secrets and variables → Actions → Variables создайте \`YOUTUBE_AUTOPUBLISH_ENABLED=true\`. Сначала запустите dry-run (не загружает).
6. При выполнении всех условий ежедневный workflow диспатчит \`youtube-direct.yml\`, тот проверяет OAuth и канал, фиксирует receipt **до** загрузки, отправляет PRIVATE+publishAt. Результат проверить в YouTube Studio и в \`publishing/receipts\`. Любую неопределённую загрузку разбирать вручную: не перезапускать наугад.

## Отчёт о блокировках
- Нет подтверждённого OAuth и EN-канала — прямой продакшн upload не доказан; никакие workflow сами не могут нажать Google Consent за владельца.
- Не настроен ключ \`YOUTUBE_API_KEY\` для \`motion-studio\` trend scan; последние измерения в \`motion-studio/data/trends.json\` устарели.
- Массовая генерация и публикация без ручной проверки качества **не включена**: её подключение требует отдельного проверенного энд-ту-энд теста, бюджетов, рабочих источников и исключения конфликтов с существующей сеткой.

## Порядок автоматизации
1. Надёжные публикации готовых видео (этот PR).
2. Периодический тренд-сканер с реальными данными (не тратить vidIQ, пока нет кредитов).
3. Бесплатная генерация и рендер **в черновик** с QA и факт-чеком.
4. RU/EN воспроизводимая очередь, аналитика удержания, оптимизация стилей — только после подтверждённых данных.
