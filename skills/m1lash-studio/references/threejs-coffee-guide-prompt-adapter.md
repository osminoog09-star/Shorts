# Адаптер мини-гайда Three.js → M1lash Мульт (04.11.2026)

Это **наши новые производственные промпты**, а не «30 промптов автора гайда». В пользовательском 5-страничном PDF есть **только один** целиком напечатанный промпт (стр.2), остальные рекламируемые промпты не приложены. Исходная задумка: 30с, вертикаль, два героя ремонтируют кофемашину, кофемашина взрывается пеной, герои довольны и пьют кофе **прямо из пены**; камера на уровне глаз, тёплый свет, подписи снизу, одна HTML-страница, запуск в браузере. Сохранять её, но рисовать только оригинальных героев.

## Промпт A — режиссура и сценарий до кода

> Создай сценарную раскадровку оригинального 3D Shorts «МИЛ и АКС чинят кофемашину» для M1lash Мульт, уже утверждённый стиль S9-D3. Главный МИЛ — оригинальный человек, АКС — оригинальный робот; никакого сходства с известными франшизами и никаких стоковых моделей. Базовая история из прикреплённого гайда: оба ремонтируют кофемашину; ИИ запускает неправильный режим; физически видимый напор пены выбрасывает их из равновесия; в финале герои **пьют кофе непосредственно из пены**, не подменяй развязку кружками. Сделай 30–40с тела, хук с действием к 2с, 6 планов по 4–7с. Для каждого плана укажи: start/end, действие, начало/конец позы каждого персонажа, точку физического контакта с кнопкой/инструментом/пеной, крупность/позицию камеры, реакцию и то, как гэг понимается без текста. Сначала предложи 6 стоп-кадров и графические риски; без кода полного MP4 до их просмотра. Живой диалог проектируй под голос Дениса (МИЛ); для АКС женский лицензированный голос только если будет отдельное разрешение/доступ. Без ТТС-подмен.

## Промпт B — визуал: настоящий Three.js, browser-first

> Реализуй принятый storyboard **в одной рабочей HTML-странице на Three.js** с локально закреплённой библиотекой, реальными 3D мешами, материалами, Key+Fill+Rim, контактными тенями, articulated rig shoulder→elbow→palm, выразительными бровями/глазами, пропсами и пеной. Не использовать VTK, PIL для зрительской сцены, апскейл 540p под видом FullHD, псевдослайды/большие текстовые панели. Добавь детерминированную `window.seek(t)`, которая без истории рендера правильно ставит все части тела и частицы; при `seek(0)` после `seek(20)` сцена должна возвращаться в исходную позу. Отрендери Playwright **6 настоящих** 1080×1920 стопов из разных планов; покажи каждый и контакт-лист. Проверяй зрительную ясность каждого кадра без надписей. Стопы с одной композицией, телепортом реквизита, рукой без контакта или непрочитываемым действием = ART NO-GO.

## Промпт C — motion pilot/acting

> Из утверждённого Three.js рендера сделай **7–10с MP4 1080×1920/30fps** самой сложной сцены (рука нажимает кнопку → машина реагирует → вырывается струя пены → брызги касаются героя → оба меняют позу). Используй Playwright deterministic frame stepping, ffmpeg H264 yuv420p. Проверь реальный MP4 кадрами не реже 0.5с на всём pilot. Обязательно: anticipation → action → recoil → hold; рука/кнопка совпадают в 3D, струя исходит из сопла, лицам не мешают реквизит и титры, тело не вылезает из 9:16 Shorts-safe area. Не запускай полный рендер, пока редактор не увидит ART PASS.

## Промпт D — звук, сборка, QA

> Только после ART PASS собери body 30–45с с настоящим голосом Дениса (локальная Qwen3 по разрешённому private reference) и, если согласован женский второй голос, с доказанной коммерческой лицензией. Не использовать новый мужской TTS/Диму как fallback; если личный ref не доступен — VOICE BLOCKED, не выдавать безголосый вариант за финальный. Для каждого сегмента зафиксировать speaker/voice_id/engine/rate/source_file, слова проверить ASR, титры синхронизировать. Концовка только утверждённый Denis v7 voice10 через `tools/assemble_with_outro.py`. Проверить финальный MP4: 1080×1920/30, H264/AAC, 30–59с с концовкой, no duplicate/outro latency, ffmpeg -xerror, `check.py`, `look.py`, 30s frame montage, видео реально оценить на художественное качество; финальный слух и разрешение на публикацию остаются за владельцем.
