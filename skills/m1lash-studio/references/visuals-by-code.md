# Картинки и видео кодом — памятка для GPT/Codex (и любого агента)

Написано 01.11.2026 (Claude) по просьбе Дениса: графика GPT «не очень получается». Основа — собственный аудит GPT `reports/research/2026-11-01_INDEPENDENT_VISUAL_AUDIT_SEVEN_MOVIES_AND_MOTION_PILOT.md` и то, что Денис уже одобрил.

## Почему сейчас выходит плохо

- Сцены рисуются **в PIL (`ImageDraw`) кадр за кадром** → плоские карточки без света, глубины и движения камеры.
- В длинном Чигуре REV14 ≈ **46 % времени — однотипные тёмно-синие карточки**: знаки «?», палочные человечки, стрелки «деньги → решение», одинаковые двери подряд, забытые надписи «ТЕСТ».
- Текст: мелкий двустрочный на тёмно-красном (не читается), крупный хук **поверх лица**.
- Пять секунд серого фона перед концовкой — зритель уходит.

Это не «недоработка деталей», а неверный инструмент: PIL — для масок и контакт-листов, не для анимации.

## Эталон качества — что Денис одобрил

- **Концовка rev4** («Отлично», 31.10): `tools/outro/outro.html` (Three.js r128, 3D-логотип, анимация по словам голоса) → `tools/outro/render.js` (Playwright + swiftshader, покадрово 30 fps) → ffmpeg. Работает в GitHub Actions без GPU. **Открой эти два файла и повторяй подход.**
- 3D-текст и бренд на сайте студии: `site/studio/i/font.json` (Unbounded ExtraBold), градиент синий → фиолетовый → розовый, тёмный космический фон.

## Чем делать (по порядку выбора)

1. **HyperFrames** (`skills/ext/hyperframes`, `hyperframes-cli`, `hyperframes-registry`) — HTML + GSAP → MP4, рендер детерминированный (перематывает таймлайн по кадрам). Локальный рендер бесплатный: `npx hyperframes render --quality delivery --output out.mp4` (нужны Node 22+ и ffmpeg; в Actions — `actions/setup-node` 22). Облако (`cloud render`) не использовать — платное.
   **Сначала ищи готовый блок в `hyperframes-registry`** (~450: кинетический текст, переходы, субтитры, графики, 3D, движения камеры) и только потом пиши свой.
2. **HTML + Three.js + Playwright** — как концовка, для 3D-сцен.
3. **Remotion** (`studio/`, скилы `remotion-*`) — если сцена уже там.
4. PIL — **только** маски, контакт-листы, служебные картинки. Сцену зрителю в PIL не рисовать.

Отдельный workflow под выпуск не заводить (AGENTS §14) — шаг рендера добавлять в общий `motion-render.yml`.

## Правила кадра

**Запрещено в готовом ролике** (если есть — ролик `DRAFT`):
- карточка «текст на однотонном фоне» как основной кадр дольше 2 с;
- знаки «?», палочные человечки, схемы «коробка → стрелка → коробка» вместо показа действия;
- один и тот же фон/цвет больше 2 планов подряд;
- служебные надписи (`ТЕСТ`, `REV`, `TODO`, имена файлов);
- статичный кадр: что-то движется всегда (минимум медленный наезд камеры 2–4 % масштаба за план).

**Обязательно:**
- План меняется каждые 5–8 с (AGENTS §10). Каждый план **показывает предмет и действие** (монета крутится, дверь открывается, прибор пищит и стрелка дёргается), а не подпись о нём.
- 3D — с деталями из `skills/vizavi-motion/references/quality-upgrades.md` (фаски, заклёпки, гравировка, текстуры, мелкий реквизит), свет ключ + контур, контактные тени. Без «пластилина».
- Движение с характером: замах перед действием, торможение в конце, лёгкий отскок (скил `emil-animate`). Линейное движение — только у камеры.
- Стиль и глубину ролика берём из `skills/vizavi-motion/references/style-library.md` по выбору Дениса (AGENTS §2). Для кинетического текста S6 — одно ключевое слово цветом, остальное белое.

**Текст (Shorts 1080×1920):**
- Ключевые слова 110–160 px, второстепенные не меньше 64 px, шрифт Unbounded ExtraBold / жирный гротеск. Не больше 4–6 слов на экране.
- Белый с тёмной подложкой или обводкой; не класть мелкий текст на насыщенный красный/синий.
- Держать в 80 % безопасной зоне: не ниже ~75 % высоты (там подпись и кнопки Shorts) и не ближе ~120 px к правому краю (лайк, комменты).
- В кино-кадре — **никогда поверх глаз и рта**: искать место по кадру (`look.py` / контрольные кадры), при нехватке места — плашка сверху.
- Каждое слово держится на экране достаточно, чтобы его прочитать (≈ 0,3 с на слово, минимум 0,8 с).

**Технически (контракт HyperFrames, верен и для своего Playwright):** время — только из таймлайна (никаких `Date.now()`, `setTimeout`, несидированного `Math.random()`), рендер покадрово с перемоткой, а не запись экрана в реальном времени; 30 fps, H.264 yuv420p.

## Порядок работы

1. **Раскадровка словами:** на каждый план — что в кадре, какое действие, как движется камера, какой текст. Если план описывается как «карточка с надписью» — переписать.
2. **4–6 стоп-кадров** из разных планов → посмотреть глазами → сравнить с концовкой. Хуже концовки — переделать до анимации.
3. **Тест 5–10 с** самой сложной сцены → посмотреть.
4. Полный рендер → проверка `skills/m1lash-studio` §2а (`check.py`, контакт-лист `look.py`); для длинного — раскадровка 1 к/с и подсчёт одинаковых планов (не больше 10 % похожих подряд).
5. Независимый аудит — `skills/m1lash-quality-improvement`. Честно писать, что сделано: 2D, 2.5D (параллакс) или 3D.

## Если не получается

Не выдавать слабую графику за готовую и не забивать время карточками. Лучше короче, но с реальными кадрами фильма (для разборов это и есть главное доказательство, AGENTS §9) — или передать сложную сцену Claude с заданием в `HANDOFF.md`.
