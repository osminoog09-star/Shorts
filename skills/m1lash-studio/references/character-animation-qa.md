## Производственный цикл для **каждого** персонажного выпуска

1. **Сценарный gate:** одна история, хук первые 2 с, причинно-следственная последовательность, понятный панчлайн. Каждая 5–8 с сцена описана пятью вещами: *действие, реквизит, жест героя, положение камеры, доказательство смысла без текста*. Если можно описать только «всплыло слово», переписать.
2. **Модели/риг:** фиксировать original character bible (цвет, силуэт, костюм, размер, два колена/локтя или иная оправданная кинематика). Нельзя «вращать руку-палку»: в модели должны существовать shoulder → upper arm → elbow → forearm → palm и пределы вращения; для робота отдельная логика мимики.
3. **6 стопов / смысл:** по одному из каждого плана, крупным отдельным файлом 1080×1920, затем контакт. Сравнить друг с другом. Принцип: **по кадру без чтения текста понятно, что происходит**; никто не перекрывает глаза; концы конечностей не обрезаны. Провал → не запускать full render.
4. **7с pilot сложного движения:** настоящий MP4 (не GIF/JPEG-превью), 30fps; распаковать и просмотр кадров по 0.5–1 с из **MP4**, а не первоначальных стопов. Проверить **anticipation → action → recoil → hold**, отсутствие телепорта/жёстких палок/выхода рук из кадра.
5. **Только после visual ART PASS:** голос отдельно по ролям и правам; speech timing/ASR, мимика и субтитры под *реальное* аудио; approved outro; затем полный рендер. Проверить official `check.py`, `look.py`, `ffmpeg -xerror`, слухом, фактами/правами.
6. **Закрытие уроков:** после каждой правки записать в отчёт `observed defect → root cause → patch/commit → artifact/run → real visual verdict`; одна-две универсальные строки в `SKILL.md §7`. Если дефект повторяется — сделать в коде проверку или preflight, не добавлять только ещё одну декларацию.

## Технические инварианты для программных 3D сцен

- Только `Three.js + Playwright` либо `HyperFrames`, кадр детерминированный `seek(t)`; PIL лишь для контакт-листа.
- Каждый joint при `seek(t)` сначала возвращается к своей базовой ориентации: старые повороты не должны накапливаться при произвольном порядке скриншотов.
- Временные кривые с `smoothstep/ease`, не переключение позы моментально по номеру сцены. Поза at 1.0/1.5/2.0/2.5/3.0/4.0/5.0/6.0 — ориентир; если состояние скачет, провал.
- На 1080×1920 UI остается в safe-area, основной герой не прячется за текстом, у всех диалогов есть отдельная реакция слушающего.
- `CI SUCCESS` означает только запуск кода и технические проверки. **Редакторский ART PASS, AUDIO PASS, READY и одобрение владельца — четыре отдельные статуса.**
- Не менять другие видео, не тратить новые деньги, не добавлять отдельные workflow на выпуск, не пушить личные голосовые WAV/MP4 в публичный Git.
