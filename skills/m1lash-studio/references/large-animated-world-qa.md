# Проверка масштабного рисованного мира (M1lash S3-D25 / 2.5D)

**Назначение:** защита от повторных ошибок «одна картинка вместо мультфильма», «мини-декорация», «технический PASS при плохой анимации». Применять ко всем новым масштабным персонажным локациям (завод/склад/парк/академия/датацентр). Следовать `AGENTS.md` и `skills/m1lash-studio/SKILL.md`; этот файл не разрешает новые форматы, публикации и расходы.

## 1. Пространство / художник

**Сцена считается масштабной, только если** на общем плане видны минимум **три настоящие функциональные зоны** с разной задачей (для завода, например, манипуляторы и сборка, транспорт и склад, контроль качества), **три различимых слоя глубины**, многоуровневая архитектура, работающие предметы; герой меньшего размера и визуально встроен в пространство. Названия зон и декорации не заменяют предметных действий. Простая иллюстрация с синусоидальным «покачиванием» — только concept art, не мультфильм.

Состав каждого `WORLD_BIBLE`: назначение зон, карта пересечений транспорта/людей, положение пола, передний/средний/дальний план, главный сюжетный предмет, источники света, цветовая контрастность, где движется камера, реквизит с размерами и z-order. Сохранять ортогональные `WORLD/HUD` координаты и исключать размещение «источника факта» на плохо читаемой поверхности.

## 2. Шесть обязательных кадров (из реального исходника)

1. Широкая экспозиция: читаются размеры здания и связи рабочих зон.
2. Транспорт/камера: техника не пропадает за конвейером без логичной окклюзии.
3. Машина в действии: контакт сварки/захвата и результат.
4. Реакция работника: не «клон человечка», различимые поза/действие.
5. Герой+реквизит крупно: глаза, ладонь, объект, цель (лоток/кнопка) видны.
6. Сюжетное последствие: предмет переместился физически, окружение ответило.

**Проверять глазами пиксели, не только JSON:** full-resolution 1920×1080 + уменьшенную до 360px ширины мобильную копию. Мелкий текст не должен быть единственным носителем факта. Рендер сцен HTML/SVG/Three/HyperFrames, а PIL разрешён только для QA-contact.

## 3. Motion/contact gate: «зацепил → перенёс → отпустил»

Для ключевого физического действия задавать **один общий event timeline**: подготовка → касание → grip → перенос → release → settle/response. Координату предмета до release вычислять из видимого сустава/кисти, а не отдельного синуса; после release — по траектории и положению лотка. Скринкасты at `t−0.2`, `t`, `t+0.2` на касании, переносе, отпускании и приземлении. Не засчитывать математический якорь, когда шестерёнка «парит» сбоку или перекрыта передней плашкой.

Проверить 3 слоя независимо: actor anatomy (рука/глаза/локти), prop contact (герой касается и удерживает объект), camera screen-space bounds (объект, кисть, цель и слова не отрезаны рамкой). **Любой NO-GO в одном блокирует full render**, даже если H264 декодируется успешно.

## 4. Camera/HUD

- `world` (SVG viewBox, zoom, pan) и `HUD` (экран 1920×1080) должны быть **отдельными** слоями; текст/логотип не должен менять размер от camera zoom.
- Для каждого plan transition просмотреть t−0.2/t/t+0.2: пересечения объектов, резкие скачки масштаба/якоря, исчезновения реквизита.
- Главное действие и цель помещать в экранную safe-zone без титров: голова, лицо, руки и ключевые подсказки в центральных ~80–85% высоты. Не скрывать объект под нижним фирменным баннером.
- Проверить как кадр выглядит на телефонной ширине 360px (сжатие изображения, не кроп): все главные предметы читаются без увеличения.

## 5. Рендер и реальные доказательства

Последовательность **6 stills → 8–10с сложного action → 15–30с связная сцена → ART QA → full**. Всегда хранить код и рендер-команду в Git. После видео: `ffprobe` exact duration/fps/codecs/frame count, полный `ffmpeg -v error -xerror -i MASTER -f null -`, реальные кадры из **декодированного MP4**, не HTML stills. Контакт из реального MP4 сам по себе не гарантирует плавность: ключевые события просматривать с шагом ≤0.5s, дополнительно слушать SFX. `TECH_PASS` ≠ `ART_GO`.

Для длинных роликов нельзя выдавать 24с MP4 за 21мин выпуск или повторять 6–8 планов сотни раз. Планировать минимум 190+ **смысловых** кадров; Qwen3 Denis должен быть реальным с проверенными WAV. Финальная QA-машина `longform_duration_gate.py` + official `check.py/look.py` + exact approved Denis v7 horizontal outro; публикация только с согласия владельца.

## 6. Журнал дефектов

В `reports/learning/journal.json` на каждый исправляемый инцидент: `id,project,issue,cause,fix,status,evidence,acceptance,owner_review,audience_effect,regression`. `status=verified` только если проведён именно описанный физический тест; иначе `observed` или `pending`. Владелец разрешил «исправить» — это не равняется ART PASS. Отчёт `longform/multnews_20261104/factory_v2/QA_v5_2026-11-04.md` — пример честного NO-GO по контакту.

## 7. Audio-zero gate (отзыв владельца 04.11 · v5→v6)

Для S3-D25 «МультНовости» после отклонения владельцем самодельных заводских звуков **все следующие немые DEMO экспортируются с `ffmpeg -an`**. Проверка не субъективная: `ffprobe -show_streams` должен вернуть **ровно 1 видео и 0 аудиодорожек**. Понижение `volume=0` недостаточно: пустой AAC тоже запрещён. Не вставлять в короткое демо моторные синусы, пищалки и синтетическую сварку «для атмосферы»; финальный **собственный голос Дениса Qwen3-TTS** остаётся отдельным обязательным требованием AGENTS §3 и не должен быть заблокирован этим gate. Дальнейшее музыкальное/звуковое оформление не вводить без нового решения владельца.

## 8. Неисправности физических сцен из реального v6 MP4

- **Сканер стационарен, предмет проходит через него.** Если камера движется, измерять координаты в world space и затем в screen space; никогда не интерполировать инспекционный луч от положения машины, иначе он «едет» вместе с ней. Момент появления только внутри соответствующей главы: `t>=20` для демо завода.
- **Окончание события — конечный таймкейс:** «ГОТОВО!» по сортировке допустимо только пока показана сортировка (`19.56 <= t < 20`). После смены плана нельзя наследовать старый статус.
- **Нет «двух лиц»:** экран корпуса — эмблема/вспомогательная информация, но не ещё пара глаз и улыбка, когда лицо уже на голове. Ноги должны визуально опираться на тень/пол; при реальной анимации тень движется с переносом веса.
- **Не смешивать stage-QA и longform-QA:** 24с `1920×1080 / 30fps / full decode PASS` не доказывает живость всех производственных операций, монтажную уникальность 21+ мин или наличие собственной авторской речи. Статусы записывать отдельно `DEMO_TECH_PASS`, `DEMO_ART_PARTIAL`, `LONGFORM_NOT_STARTED`.

**Фактический пример:** `longform/multnews_20261104/factory_v2/QA_v6_2026-11-04.md`: настоящий silent MP4 с 0 audio streams, v5→v6 timecode-audit, открытые ART-дефекты первых 16 секунд.

## 9. Cross-world event continuity (05.11 · Factory v7 + Warehouse v1)

**Кран, погрузчик, вакуумный захват и конвейер проверяются как один физический объект по фазам:** `source` → `approach` → `contact` → `grip` → `lift` → `travel` → `lower` → `release` → `settle`. Истинная координата коробки/кузова при мгновении смены attachment state должна совпасть с исходной world позицией в пределах 1–2px, включая ориентацию и масштаб. Не достаточно, чтобы `event=true` и FFmpeg были зелёными: проверить **физически декодированные кадры** до/в/после release, а затем крупный план 360px, чтобы зритель понял задачу.

**Сварка — наконечник + кузов + искра в одной точке.** Не рисовать независимые случайные spark координаты. В factory v7 `window.__weldQA` сохранила `toolTip, target, delta`; условие `delta≈0` на контакт t9.05–10.65 и `contact=false` в остальные фазы. В старом v6 технический decode был PASS, но этот гейт нарушался. См. `longform/multnews_20261104/factory_v2/QA_v7_2026-11-05.md`.

**Новая локация = не смена названия на старом фоне.** Для warehouse v1 отдельно создано 8 фактических stills, иной floor plan, док/фура, 6 секций стеллажей, мобильный robot-gripper, сортировочная лента и scanner. Даже при 480 кадрах H264 без аудио это **ART PARTIAL**: стеллажи повторяются и рабочие статичны. Без 3–5 дополнительных сюжетных операций не растягивать 16с эпизод в трёхминутную главу, не выдавать «масштабный фон» за сыгранную сцену. См. `longform/multnews_20261104/warehouse_v1/QA_v1_2026-11-05.md`.

**Приёмка ролика и ответственность:** у каждого кейса отдельно `TECH_PASS` (реальный MP4/кадры/streams), `CONTACT_PASS` (точка события), `STAGING_PASS/FAIL` (состав/масштаб), `ART_GO/NO_GO` (проверка действия в движении), `OWNER_REVIEW`. Записи в журнале помечать `verified` только по проведённым тестам, не подменять общим техническим PASS.

## 10. Лаборатории обучения: телеприсутствие ≠ автономность (06.11)

- При визуализации реальных публичных лабораторий и фабрик данных показывать, **кто управляет роботом**. Отдельный оператор, движение перчатки/руки, линия передачи или запись примера — не выдавать управляемую демонстрацию за самостоятельную способность выполнять все бытовые задачи.
- Для переноса предметов: один физический event (approach→grip→carry→release→settle), координаты чашки до и после переключения attachment равны, для grip проверять gap≈0 и **реальные декодированные кадры** t−0.2/t/t+0.2. Ни operatorDriven=true, ни gripGap=0 не заменяют художественный просмотр.
- Комиксная академия должна иметь разные самостоятельные действия в кухне, белье и имитаторе машины. Неподвижные стены и один робот не образуют 3-минутную полноценную анимацию. **ART PARTIAL**, пока операторы не играют и предметное действие есть лишь в одной зоне.
- Выводы о разрешении/кадрах брать по **ffprobe реального MP4**. Размер viewport браузера может не совпадать с фактическим screenshot SVG, если CSS фиксирует ширину элемента. В filename не указывать 720p, если файл 1920×1080. Прерванный по таймауту процесс рендера — не TECH PASS сам по себе, даже если файл уже возник: отдельно ffprobe, полный ffmpeg -xerror, 1fps QA.
- Пример: longform/multnews_20261104/lab_gpt_20261106/QA_v1_2026-11-06.md, 18с, реальные 540 H264 кадров/0 audio streams, но **ART PARTIAL** по игре оператора и наполнению среды.
