# Бюджет рендера и параллельный рендер

Измерено на ролике «Антикитерский механизм» (Three.js, PBR, VSM-тени, Bokeh, MSAA 4×, 1920×1080):

| Среда | Время на кадр |
|---|---|
| Облачная сессия, 2 CPU, без GPU (SwiftShader) | ≈ 5–6 с |
| Без Bokeh | −1,5…3 с |
| Без теней | −1…1,5 с |
| Без MSAA | −1…2 с |

Правила:
- Длинные видео (> 3 мин) — **30 fps** по умолчанию; 60 fps удваивает рендер без заметной пользы для плавной студийной камеры.
- Не рендери длинное видео в одной сессии. Используй workflow `Render long video` (`.github/workflows/render-long.yml`):
  кадры делятся на N кусков (по умолчанию 20 параллельных задач), затем склейка + звук, результат коммитится в `videos/long/`.
- Лимит бесплатного GitHub — 20 одновременных задач на аккаунт. Если параллельно рендерит другой агент — встанешь в очередь,
  закладывай запас времени (≈ 1–2 ч на 10-минутный ролик).
- Перед полным рендером: контактные листы стоп-кадров (по 2 на сцену) и короткая проба риска. Полный рендер — только после них.
- Детерминизм: `renderAt(t)` зависит только от `t`; никаких `Date.now()`, случайных чисел без seed и накопления состояния между кадрами —
  иначе куски, отрендеренные на разных машинах, не стыкуются.
- Шрифты загружай ДО создания сцен (текстуры подписей рисуются при создании); иначе в спрайтах будет запасной шрифт.
