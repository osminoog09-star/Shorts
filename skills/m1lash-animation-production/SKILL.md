# M1lash Animation Production · аниматор и технический продюсер
**Правило 28.10.2026:** новые полноценные длинные видео — минимум 21:00 (1260 секунд), ориентир 23–28 минут; не растягивать пустыми кадрами/повторами/музыкой. Перед новым релизом выполняется python scripts/qa/longform_duration_gate.py FILM.mp4. Короткие аниматики и тесты не являются длинными выпусками. Новое правило выше всех старых 10–15 минут.


Стартовать только после `m1lash-director`: `shotlist.csv`, `animatic.mp4`, утверждённые model sheets и разрешённые ассеты. Читать правила `AGENTS.md` + `skills/vizavi-motion/SKILL.md`.

## Конвейер
1. Сделать `assets_manifest.json`: уникальные герои, локации, предметы, SFX, музыка, источник/лицензия, версии.
2. Отдельные слои персонажей: туловище, голова, волосы, глаза, рот, руки, кисти, одежда, тени. Для 3D — риг, shape keys/виземы.
3. Сгенерировать 4–6 тестовых кадров из **разных локаций** + 15–30 с анимации с диалогом/движением/взаимодействием, прежде длинного экспорта.
4. Анимировать сцены в соответствии с shotlist. Выразительные keyframes, anticipation, follow-through, ease-in/out, вторичная динамика, реальная артикуляция и удержание объектов.
5. Синхронизировать lip-sync по `WordBoundary` или Rhubarb, не по случайному синусу; не делать вид, что lipsync точен, если нет данных.
6. Голос: **Дима** (`ru-RU-DmitryNeural`) — основной голос автора/ведущего во всех новых RU-выпусках, **Света** (`ru-RU-SvetlanaNeural`) — второй голос для женских ролей и диалогов. Не заменять автоматически на Liam/Piper/eSpeak, в том числе в CTA; архивные записи с другим голосом нельзя повторно использовать в новом выпуске. В манифесте фиксировать `voice_id` каждого сегмента, пересчитывать липсинк; при недоступном Диме — NO-GO.
7. Рендер сцен **по отдельности** в стабильном FPS/разрешении, с промежуточными валидными MP4. Не пытаться писать весь длинный 21+-минутный фильм одним нестабильным процессом.
8. Склейка с одинаковыми кодеками/timebase и проверкой A/V; музыка тише речи, SFX по действию; титры и финал отдельным слоем.
9. Финальный MP4 H.264 yuv420p/AAC, 16:9 1920×1080 по правилам (ниже только по сознательному решению и маркировать как черновик). Исходники сохранять.

## Жёсткие проверки
- duration audio/video drift <=0.25 с, финальный декод полного файла без ошибок.
- Проверка tail: точки `D-30,D-15,D-8,D-2,D-0.5` со звуком/стоп-кадрами. Звуковой CTA и последнее движение действительно присутствуют.
- Авто-поиск чёрных кадров, внезапных freeze, немотивированной тишины >2 c, субтитров за границами. Тишина только по сценарию.
- Разрешение, цвет, громкость, характерная скорость голоса, непрерывность монтажной последовательности.
- Визуальный аудит **не равен** ffprobe: смотреть минимум каждый уникальный план и все переходы, отчитаться, что просмотрено.
- Статус `DRAFT` до принятия `m1lash-quality-improvement`, затем `RELEASE_CANDIDATE` и только после ручного зрительского просмотра `APPROVED`.
- Не объявлять «профессиональное 3D», если сделано простым 2D или параллаксом.

## Повторное использование
Библиотека совместимых персонажей/риггов, локаций, камер, света и переходов; не штамповать одинаковый офис всю историю. Каждое изменение ассета — версия с контрольным скрином.

## Обновление 2026-10-27: урок V1 → V2 кодовой анимации
См. `docs/M1LASH_CODE_ANIMATION_V2_REVIEW.md` и источники Disney Animation / Blender / Microsoft.
1. К каждому ключевому действию создавать четыре позы: подготовка (anticipation), контакт, реакция, завершение (settle); все фазы видны в full-motion MP4.
2. Для реквизита проверять **физический контакт**: кисть достигает кнопки, кнопка действительно нажимается и реагирует, другие персонажи замечают событие. Шевеление руки без контакта = NO-GO.
3. Раздельно анимировать взгляд, брови, голову, плечи, кисти и корпус, с осмысленным запаздыванием, не одним синусоидальным движением для всех.
4. Перед рендером утвердить пропорции, силуэт, лица и единый модельный лист. Процедурные человечки с круглыми головами не заменяют утверждённые персонажи.
5. Метрики 1fps/SSIM фиксировать только как диагностические. V1 → V2: 5.78→5.97/255 изменения, 4/11 статичных переходов остались. По таким цифрам не заявлять рост художественного качества.
6. Режиссёрское GO требует покадрового просмотра реального движения, артикуляции, непрерывной речи и финала. Изолированная немая видеопроба отмечается как TEST, а не финальный клип.


## Критический аудит CODE V3 (27.10.2026) — новый художественный gate
Документ: `docs/M1LASH_CODE_V3_FULL_AUDIT_20261027.md`. Проверка реального пользовательского MP4, не самоотчёта.
- **Запрещать** персонажей, у которых кисти — окружности, плечи/локти — палки, «мимика» — одна открытая буква O. Контур руки, ладонь и минимум 4 пальца должны читаться на общем и крупном плане.
- Художественный `NO-GO`, даже если FFmpeg показывает PASS: низкое качество силуэта, симметричный «руки вверх» без подготовки/шага/эмоций, дубли персонажей разного масштаба, плоское одинаковое окружение.
- Вводить `MODEL_GATE`: 3 ракурса одного героя, 6 независимых выражений, 4 силуэта действий; при расхождении дизайна между ракурсами — запрещать сценовый рендер.
- Вводить `CONTACT_GATE`: реальный палец нажимает кнопку (перемещение реквизита видно), рука сгибается в правильных суставах, центр тяжести и пол согласованы; не признавать «кисть нацелена на точку» за физический контакт.
- `ACTING_GATE`: в 15-сек сцене должны читаться пять причинных фаз действия + асимметричная реакция персонажа, понятная без звука.
- Метрика V3: 11/23 полусекундных соседних переходов почти статичны при пороге mean diff <3/255 (96×54); резкие дельты на 4-й и 8-й секундах — склейки. **Не оптимизировать эту метрику вместо качества**.
- Реализация: принцип staging, anatomy, appeal, anticipation и overlapping action из Disney/Meta; Grease Pencil/shape keys/IK из Blender — `Pillow` не основной художественный движок, если качество героя провалено.

## V4 self-audit lesson — frame-first physical contact checks (2026-10-27)
- Before encoding, render representative stills at anticipation, contact, maximum press, release and settled frames and visually inspect **layer ordering**. First V4 export had its sleeve hiding the hand, and was rerendered after this was spotted.
- Model, stage, contact, acting and audio quality gates are INDEPENDENT. Technical decode PASS cannot override visible bad anatomy.
- The press/contact test needs real fingertip-to-prop screen-space distance and prop travel verification, plus visual inspections for sleeve/palm overlap; mathematical IK is not adequate on its own.
- Keep reusable vector geometry and independently interpolated elements instead of fake camera pans. However geometric SVG bodies are not inherently attractive: art direction and character silhouette must pass before long renders.
- The 9-second V4 reference is intentionally SILENT. Do not mislabel it as a narrated release or replace narrator Dmitry without explicit permission. See docs/M1LASH_CHARACTER_V4_SELF_AUDIT.md.

## Новый урок V6 · реальный тест контакта пальца
Перед рендером проверять координаты пальца относительно хитбокса предмета. В кадре контакта кончик пальца должен опираться на поверхность, а не проходить сквозь её геометрию. Проверять t-0.2s, t, t+0.2s: ладонь, другие пальцы, складка рукава, ход кнопки. Числовое попадание в область без правдоподобного визуального контакта = NO-GO. См. `docs/M1LASH_V6_HAND_CONTACT_AUDIT.md`.

## ОБЯЗАТЕЛЬНЫЙ PRODUCTION RESET 2026-10-28
Последовательность микро-роликов S1 V1–V8 завершена из-за отсутствия прогресса (герои 3–5/10). Основной документ: `docs/M1LASH_S1_PRODUCTION_RESET_20261028.md`. **Следующий пользовательский результат обязан быть цельным 30–60-сек сюжетным MP4 с оригинальной озвучкой Дмитрия**, а не немым 4–14-сек примером отдельной руки. В одном производственном пакете одновременно решать персонажей, движения, режиссуру, фон, аудио, финал; внутренние микропробы не подавать как готовую версию. До full film выполнить model sheet/shotlist/animatic, затем все планы сцены, audio, QA и устранение P0/P1. Source code и ассеты сохранять в GitHub, а не одни QA-отчёты. Release gate — >=8/10 по каждому из восьми художественно-технических критериев, иначе честное NO-GO. Не обещать фоновую автономную работу.
