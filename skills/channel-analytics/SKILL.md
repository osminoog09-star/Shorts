# Аналитика канала M1lash

Цель — не отчёт ради отчёта, а **знание, которое меняет следующий ролик**. Каждый разбор заканчивается конкретными
правками: что повторить, что убрать, что попробовать. Всё по-русски, коротко, с цифрами.

Файлы:
- `reports/videos.csv` — **журнал всех роликов** (одна строка = один ролик): метаданные + метрики. Единый источник для расчётов.
- `reports/learnings.md` — **база знаний**: выводы с доказательствами и уверенностью. Её читают перед каждым новым роликом.
- `reports/style_experiment.md` — эксперимент стилей; `skills/vizavi-motion/references/style-library.md` — коды стилей.
- `STRATEGY.md` — решения на неделю/месяц (их меняют недельный и месячный отчёты на основе learnings).
- `tools/analytics/analyze.py` — расчёты по `videos.csv` (медианы, «индекс залёта», сравнение групп).

## 1. Собрать данные

Источники по порядку (бери что доступно, отмечай пропуски — не выдумывай):
1. **Metricool** (бесплатно): `getAnalyticsDataByMetrics`, brand `7605462`, поля по роликам
   `YTVP02` дата, `YTVP04` id, `YTVP17` название, `YTVP06` просмотры, `YTVP08` средняя длительность просмотра,
   `YTVP09` лайки, `YTVP11` комментарии, `YTVP12` репосты; канал — `YTEV01/05/06` подписчики/пришло/ушло, источники — `YTTS01/02`.
   Данные YouTube в Metricool приходят с задержкой 1–3 дня — свежие ролики могут быть пустыми.
2. **vidIQ** (платно, кредиты): `vidiq_video_stats`, `vidiq_channel_videos`, `vidiq_channel_analytics`. Сначала `vidiq_balance`; кредиты береги для голоса.
3. **YouTube Studio** — кривая удержания и «Смотрели / Пролистали» есть только там. Для лучшего и худшего ролика недели
   попроси Дениса прислать скрин вкладки «Аналитика → Охват/Вовлечённость» ролика (одна просьба в недельном отчёте).
4. Свой контент: файл ролика в `videos/`, сценарий/таймлайн в репо, транскрипт — смотри первые 3 с и стоп-кадры глазами.

Внеси/обнови строку в `reports/videos.csv` для каждого ролика (возраст метрик фиксируй: `views_48h`, `views_7d`).
Новые ролики добавляет сам агент, который их публикует (дата, id, формат, стиль, тема, длина) — метрики дописывает аналитика.

## 2. Посчитать

`python3 tools/analytics/analyze.py` — печатает:
- **Индекс залёта** = просмотры за 7 д ÷ медиана 7 д последних 15 Shorts (до 7 дней — то же по 48 ч).
  ≥ 2.0 — залетел, 0.5–2.0 — норма, ≤ 0.5 — провал. Длинные считаются отдельно от Shorts.
- **Досмотр** = средняя длительность ÷ длина ролика. Ориентиры для Shorts (эвристика, не закон): ≥ 80% сильно, 60–80% норма, < 50% слабо.
- **Вовлечённость**: лайки/просмотры, комментарии/просмотры, репосты/просмотры (репосты — самый сильный сигнал «зацепило»).
- **Группы**: по формату, стилю, глубине, теме, длине (≤30 / 31–45 / 46–60 / >60 с), слоту и дню, автору (Claude/Codex).
  Вывод по группе — только при n ≥ 3; при меньшем — «гипотеза».

## 3. Понять почему (для каждого залетевшего и каждого провала)

Сравнивай с похожим роликом, который отличается по одному-двум признакам. Пройди чек-лист и отметь, что объясняет разницу:
- **Первые 2 секунды**: есть ли конфликт/вопрос/шок в первом кадре и первой фразе; текст на экране; лицо/движение.
- **Тема**: горячая ли (тренды, поиск), понятна ли без контекста, «узнаваемая боль».
- **Обещание и развязка**: одна история, обещание в начале, выплата в конце, есть ли повод пересмотреть (луп).
- **Темп**: смена кадра каждые 2–5 с, нет провисаний; длина соответствует истории (досмотр падает — режь).
- **Подача**: стиль/глубина, ведущий, голос, музыка, кинетический текст, громкость.
- **Упаковка**: название (интрига, без спойлера), первые слова описания, хештеги, обложка (у длинных).
- **Публикация**: день/время, сколько роликов вышло в тот же день, Content ID-претензия (ограничивает показ).
- **Источник трафика** (Metricool `YTTS`): лента Shorts vs поиск vs внешние — залёт почти всегда из ленты.

Формулируй как гипотезу с уверенностью: *низкая* (1 ролик), *средняя* (2–3 согласных случая), *высокая* (≥ 4 и нет противоречий).
Не путай корреляцию с причиной; не делай выводы по роликам разного возраста.

## 4. Что доработать

- Для провала — 1–3 конкретные правки, которые бы его спасли (пример: «хук перенести на 0 с — сейчас конфликт начинается с 4 с»,
  «срезать 8 с середины», «название раскрывает развязку»). Перезаливать или менять опубликованное — **только с решения Дениса**.
- Для залетевшего — что именно повторить и как масштабировать (серия, продолжение, тот же приём в другой теме).
- Для движка/пайплайна — задача в `STRATEGY.md → «Задачи для движка»`, если проблема системная.

## 5. Записать знание

`reports/learnings.md`: добавь/обнови пункт в формате
`- [уверенность] Наблюдение — доказательство (id роликов, цифры) — что делать.`
Подтвердилось ещё раз — подними уверенность; опровергнуто — перенеси в «Опровергнуто» с датой. Не больше ~40 активных пунктов.
Решения на следующий период — в `STRATEGY.md` (недельный/месячный отчёт).

## 6. Отчёт Денису

Коротко (≤ 15 строк): цифры периода, топ и провал с объяснением «почему» в одну строку, 3 решения, 1 просьба (скрин/решение).
Полная версия — `reports/weekly/<год>-W<нн>.md` или `reports/monthly/<год>-<мм>.md`.

## Перед новым роликом (для агентов-продюсеров)

Прочитай `reports/learnings.md` (раздел «Работает») и используй пункты со средней/высокой уверенностью.
Стиль и глубину спроси у Дениса по правилу эксперимента (AGENTS.md), предложив 2–3 кода и причину из learnings.
После публикации добавь строку в `reports/videos.csv` (без метрик).
