## Один раз нужен Google Drive OAuth

Права `anyone=writer` на папке **не дают** GitHub Actions полноценного OAuth API-доступа. Не хранить Google токены в исходниках или в чате.

1. На своём компьютере установить [rclone](https://rclone.org/downloads/) и выполнить `rclone config`.
2. Создать remote с именем **m1lash**, тип **Google Drive** (`drive`), авторизоваться именно владельцем папки. Google рекомендует собственный OAuth Client ID/Secret; для rclone использовать OAuth client типа **Desktop app** с соответствующей конфигурацией. Права Drive выбираются при подключении.
3. Через `rclone config file` открыть файл конфигурации; убедиться в разделе `[m1lash]` и действительном токене (`token = {...}`). Не отправлять его в чат.
4. Поместить **весь** файл конфигурации как секрет `GDRIVE_RCLONE_CONFIG` в `https://github.com/osminoog09-star/Shorts/settings/secrets/actions`. Он будет записан в файл только во временной среде runner и удалён после обработки.
5. Если выбрать `Скачать в Drive` раньше настройки, workflow должен **честно завершиться ошибкой** `setup_failed`; команда не должна скачивать фильм и тратить трафик напрасно. Режим «Проверить качество» секрет не требует.

**Безопасность папки:** верни «Все, у кого есть ссылка» из Writer в Reader; владелец через свой OAuth и так может туда писать, а публичная запись даёт сторонним людям опасные права.

## Ограничения и QA

- HDRezka может блокировать IP GitHub Actions; установлен `--no-antibot-solver` — при challenge честная ошибка, никаких прокси/cookie/CAPTCHA bypass.
- 1080p иногда Premium-only; бесплатно не подменяем его тизером. 720p тоже запрашивается строго, без апскейла.
- Код проверяет высоту видео `>=720/1080` и длительность `>=20 мин`, чтобы не перепутать с рекламным/коротким фрагментом.
- Runner временный, загрузка большого фильма может упереться в диск, сеть, лимит времени или Google Drive quota.
- Последний статус общей очереди, а не персонифицированная история по фильмам. Открытая страница не показывает видеофайлы и ссылки.
- Для 9:16 Shorts **1080p лучше**, поскольку из исходного 1920×1080 можно кропнуть центральные 608×1080; из 1280×720 останется 405×720.
- Собственное разрешение владельца студии не заменяет разрешение правообладателя. Отрывки и публикация контролируются отдельно правилами AGENTS §8.

## Обновление 02.11 — подключение Google Drive без ПК

- Реализован секрет **`GDRIVE_REFRESH_TOKEN`**, записываемый владельцем через «Студия M1lash» → ⚙️ → «Google Drive — загрузка фильмов». Поле вызывает уже существующую `setSecret` (публичный ключ GitHub + шифрование на устройстве); значение **не сохраняется** в localStorage, в Git и в отчёт.
- Google OAuth client ID/secret берутся из **существующих секретов YouTube** `YOUTUBE_OAUTH_CLIENT_ID` и `YOUTUBE_OAUTH_CLIENT_SECRET`; второй клиент не нужен. Сфера разрешения **`https://www.googleapis.com/auth/drive`** настраивается в OAuth Playground через «Use your own OAuth credentials», используя тот же Google Cloud проект. Этот scope даёт доступ ко ВСЕМ файлам Drive, не только к папке — владелец должен понимать и явно авторизовать.
- Новый `scripts/drive_oauth_config.py` конструирует `[m1lash]` rclone.conf только в `$RUNNER_TEMP`; сохраняет `0600`, запускает `rclone lsf m1lash:` для проверки нужной папки. Прежний полный конфиг `GDRIVE_RCLONE_CONFIG` оставлен как fallback.
- `hdrezka-intake.yml` теперь имеет режим `drive_check`: он проверяет Google Drive без обращения к кино-сайту, пишет только `publishing/drive_auth_status.json` (`connected=true/false`), после чего запускается штатная публикация GitHub Pages. Режим `download` до скачивания требует успешной проверки доступа.
- В «Клипы» добавлен индикатор Drive, кнопка входа в настройки. Кнопка «Скачать в Drive» заблокирована до успешной проверки OAuth. `site/studio/auto_refresh.js` обновляет состояния без перезагрузки.
