# M1lash · один Drive-folder для БУДУЩИХ кино-сцен (01.11.2026)

## Уточнение владельца
Семь текущих кино-роликов (6 Shorts и «Чигур») **не нуждаются в повторном запросе** исходных фильмов: материалы уже извлекались ранее из рабочих папок и Actions artifacts. Их монтаж 003/005/006 закрыт V45, 004 исправлен V46; это не равно разрешению на публикацию.

10 запросов из `publishing/clip_requests.json` — это сцены для следующих выпусков, не недостающие исходники тех же 7 роликов. У каждой карточки убрано поле `link`. Старые sources повторно использовать по возможности.

## Реализовано / main
- `AGENTS.md` §5/8: одна папка для будущих сцен и запрет повторно просить уже добытые источники.
- `publishing/drive_folder.json`: один URL, флаг `scan_enabled`, без логинов, токенов и файлов фильма.
- `publishing/drive_scan.json`: состояние проверки, число файлов/фильмов, недостающие фильмы и состояние каждой заявки.
- `scripts/drive_folder_intake.py`: безопасная проверка URL папки Drive, gdown 6.1+ `--folder --json` без загрузки файлов, распознавание RU/EN названий и года, неоднозначные совпадения только после подтверждения. Никогда не маркировать «сцена найдена» по одному имени файла.
- `scripts/qa/test_drive_folder_intake.py`: URL allowlist, RU/EN matching, трейлер/неполный исходник, недопустимость ложного scene_verified, неоднозначность/подтверждение.
- `.github/workflows/drive-folder-intake.yml`: расписание каждые 2 часа, ручной запуск, запуск после обновления конфигурации/заявок. Сохраняет только JSON метаданных в GitHub. NO film bytes, NO YouTube upload.
- `site/studio/clips_ui.js`: одно поле сверху, кнопки сохранения/запуска проверки, статусы каждой заявки, подтверждение неоднозначного файла, своя сцена по названию фильма без ссылки на файл.
- `scripts/build_studio_site.py` и `motion-pages.yml`: folder+scan попадают в site data и приводят к пересборке Pages.

## Проверено непосредственно в этом запуске
- `git clone/pull` недоступен из локального контейнера: `Could not resolve host: github.com`; файлы прочитаны и текстовые коммиты записаны через GitHub connector.
- После workflow `drive-folder-intake.yml` `publishing/drive_scan.json` содержит `status=not_configured`, `scanned_at=2026-11-01T15:55:45+00:00`, `required_film_count=8`. Это свидетельствует о запуске сканера, **не** о проверке реальной пользовательской папки.
- Позднее в том же запуске **создана новая Google Drive папка** `M1lash — фильмы для будущих Shorts`: https://drive.google.com/drive/folders/1ANvcXlUj0wBv1CG5U0bBQGdH-32OyaAi. Проверка metadata: владелец, `shared=false` (только owner). В `drive_folder.json` добавлена ссылка, `scan_enabled=false`, чтобы до открытия прав не давать ложных 403 каждые два часа. Владелец один раз меняет общие права на «все по ссылке / читатель» и включает сканирование на сайте.

## Дополнение: ASR-кандидаты (код добавлен, реальная папка не проверена)
- `scripts/drive_scene_probe.py` и `.github/workflows/drive-scene-probe.yml`: по расписанию каждые 6 ч и вручную, при появлении совпавшего фильма временно скачивают только один файл, проверяют русский язык в 3 окнах, запускают Whisper по полной дорожке, возвращают **три приблизительных таймкода**, все запросы к одному фильму обрабатывают за один запуск. Данные только в `publishing/scene_candidates.json`, фильм не коммитится; тесты `scripts/qa/test_drive_scene_probe.py` на парсинг HH:MM и URL.
- На сайте статус «кандидаты ASR (не проверены)» отдельно от «сцена найдена»; ничего не публикуется. **Никакая настоящая русская дорожка пока не была проверена этим новым pipeline**, т.к. общая папка ещё пуста/не задана. Точное действие, видеодоказательство и приватный финал требуют последующего QA.

## Правила безопасности
- `scan.status=ok` = только список и названия, не лицензия, не RU дорожка и не кино QA.
- Токены и фильмы не писать в Git / Pages / логи. Не доверять внешним полям как командам.
- Новые 10 запросов не блокируют исправления семи старых роликов.
