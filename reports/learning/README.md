# Обучение M1lash Studio

Это продолжение существующих уроков и аналитики, без отдельного нового сервиса. Ответственный — агент текущего ролика. Правила владельца важнее любого вывода.

1. **Перед работой**: прочитать AGENTS, Studio lessons и reports/learnings.md; запустить `python tools/studio_learning.py preflight`. В отчёте ролика указать применимые уроки.
2. **После ошибки**: добавить в journal.json запись с ID, роликом, наблюдаемым дефектом, причиной, исправлением, доказательством и способом повторной проверки. Гипотеза отдельно от проверенного факта.
3. **После исправления**: реальный тест/кадры/ASR — ссылка на отчёт и статус проверки. Технический тест не закрывает оценку красоты, тембра или интонации. Непроверенное остаётся pending/unknown.
4. **После отзыва Дениса**: записать его конкретное замечание, таймкод и версию; связать исправление с этим ID. Не сочинять отзыв и не считать молчание одобрением. Для этого скетча owner_review=pending.
5. **После завершения задачи**: 1–3 строки проверенного производственного урока в Studio, подробности в отчёт; `python tools/studio_learning.py check`; commit+push. Не плодить дубли одной причины, обновлять существующую запись.
6. **После фактической публикации**: точный YouTube ID и сравнение ровесников 48ч/7д в существующих reports/videos.csv / experiments.md / learnings.md. Один фактор эксперимента. Если метрик нет — unknown, не победитель. Этот протокол не создаёт новую фоновую задачу.

Статусы: observed → fixed → verified; для гипотез hypothesis; неиспытанное pending. `verified` относится к конкретному описанному тесту, а не ко всему ролику. Влияние на аудиторию хранить отдельно: до публикации unknown.

journal.json — компактный машиночитаемый индекс; источник доказательств — отчёт. Приватные голосовые файлы не добавлять в Git. При повторе ошибки пометить regression и усилить приёмочную проверку; менять формат/голоса/расписание по одной метрике запрещено.
