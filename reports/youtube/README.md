# YouTube Analytics — M1lash (Codex)

Правила: AGENTS.md §13; методика: skills/channel-analytics/SKILL.md.

## Сбор

`.github/workflows/youtube-analytics.yml`: ежедневно 07:20 UTC (09:20 зимой / 10:20 летом в Таллине), вручную через workflow_dispatch и при изменении самого сборщика в main. YouTube используется только на чтение. OAuth — `token_for('ru')`, с проверкой канала по `publishing/channels.json`. Новые секреты не нужны.

- `daily/YYYY-MM-DD.json` и `.md` — снимок по дате Таллина; JSON содержит весь каталог uploads (с пагинацией), метрики каждого видео, состояние канала, просмотры по дням и трафик каждого видео за последние 28 дней.
- `latest.json` — тот же JSON для страницы `publishing/studio/`; Claude подключает его к своему интерфейсу. Схема v1: `snapshot_date`, `fetched_at`, `channel_id`, `start`, `end`, `inventory[]`, `videos[video_id]`, `traffic.videos[video_id][]`, `unsupported_metrics`, `limitations`.
- Метрики: views, engagedViews, averageViewPercentage, averageViewDuration, subscribersGained/Lost, likes, comments, shares, estimatedMinutesWatched. HTTP 400 конкретной метрики отмечается как недоступность; 401/403 и сетевой сбой прерывают сбор. В логи не попадают токен и тело ошибки.
- `reports/videos.csv`: метаданные и прежние измерения сохраняются. Новые текущие значения — только `yt_*`, границы `analytics_start/end`, время `analytics_as_of`. Неизвестные видео имеют `kind=unknown` до сверки; по одной длине Shorts не определяется, по похожему названию запись не склеивается. Приватные загрузки не получают выдуманную дату публикации.
- При конкурирующей записи rebase не перезаписывает чужую работу; при конфликте job завершается с ошибкой, результаты остаются в Actions artifact.

## Время и ограничения

Дни YouTube Analytics — America/Los_Angeles, дата файла — Europe/Tallinn, fetched_at — UTC. Запрашивается максимум вчерашний завершённый день Pacific. Данные YouTube могут отставать; `last_observed_view_day` — последний день с возвращённой строкой просмотров, это НЕ гарантия готовности остальных метрик. Все снимки/периоды предварительные и могут уточняться.

Пустая строка API и отсутствующая метрика — `null`, не 0. Явный ноль сохраняется. `inventory[].statistics` и `channel_statistics` — пожизненные Data API счётчики на момент сбора; `videos` — Analytics за start/end. Эти величины нельзя смешивать. AverageViewPercentage — показатель API; он может быть >100%, не ограничиваем его вручную.

Точные скользящие 48ч/7д после часа публикации из дневного API не восстановить. `views_48h` / `views_7d` остаются пустыми, если нет отдельного достоверного измерения; текущие или календарные просмотры туда не подставляются. Для сравнения ровесников нужны отдельные сопоставимые наблюдения либо явно обозначенные календарные окна. analyze.py читает только возрастные поля и не выдаст текущие метрики за 7-дневные.

## Недельный и месячный разбор

Сборщик каждый день обновляет числовую основу последней недели в `reports/youtube/weekly/` и прошлого месяца в `monthly/`. В воскресенье недельный период включает текущую неделю: воскресенье ещё не завершено, это явно предварительный отчёт. На последующих запусках он уточняется. Месячный период — прошлый календарный месяц. Границы API указаны внутри файла; они Pacific, не часовые интервалы Таллина.

Автоматизация **M1lash — аналитика канала** (Codex, ежедневно около 12:00 Europe/Tallinn) проверяет свежесть/ошибки, по воскресеньям готовит полный `reports/weekly/YYYY-Www.md`, 1-го — `reports/monthly/YYYY-MM.md`, затем уточняет запоздавшие данные. По методике она изучает содержание лучших/худших, отделяет гипотезы от причин, даёт 3 решения, расход, одну просьбу о Studio-скринах, обновляет `learnings.md`, текущую стратегию в `STRATEGY.md` и HANDOFF. При совпадении воскресенья и 1-го делает оба отчёта. Первые сроки: 01.11.2026 (неделя W44 и октябрь).

Производство/публикации эта инфраструктура не запускает. Платные источники не нужны. AGENTS имеет приоритет над устаревшими советами скила.

## Проверка

`python -m unittest discover -s tests -p 'test_youtube_analytics.py' -v`

Тесты без OAuth: пагинация отчётов и uploads, неизвестные/нулевые метрики, запрет скрытия ошибки прав, календарные границы, сохранность редакционных полей и точных возрастных измерений. Фактический доступ Analytics подтверждает только успешный Actions run, не эти тесты.
